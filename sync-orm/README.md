# Sync ORM

This package provides generic SeaORM persistence and declarative source-row bindings for the neutral [Sync engine](../sync/README.md). Rune source-row ownership and application composition belong to [the integration specification](../documents/sync-integration.md).

## Declarative source-row bindings

The adapter supports caller-owned entity policies in addition to accepted-state persistence. A policy declares one source UUID, portable columns, local columns, UUID references, insertion defaults, scalar limits, identity validation, removal behavior and original-author restrictions. The caller registers its policies once. The registry generates the collection/tag/value dispatch required by `SyncModel` and supplies initialization traversal from that single registration list.

`RowPolicy<E, M>` is the shared SeaORM executor for an entity and its generated field mapping. Ordinary callers declare fields and rules; the executor supplies insert, update and delete operations. Portable values are decoded and validated before mutation; conversions reject overflow, invalid nulls and wrong scalar types. Existing source rows are found by their unique UUID. An update writes owned portable columns and declared local adjustments. An insertion uses explicitly declared local defaults or database defaults. A removal affects the source row and its declared owned rows. The caller supplies and commits the transaction used by `project_on`. The convenience `project` method opens and commits a standalone transaction.

Queries select the primary key, source UUID, portable columns and explicitly declared `local_reads`. Local binary bodies are fetched only through declared reads. Pure owner, derived-value and local-adjustment functions receive a `RowView<E>` with typed column access; reading an unselected column is an error. Local adjustments are restricted to declared local columns.

Policy declarations produce a typed portable value and its encoder/decoder. The registry generates model dispatch from those types. The declarative macro and typed column descriptors generate the model's dispatch expressions from the registry. Registry construction checks duplicate tags/fields, column ownership, reference targets and unsupported scalar types before a store is used.

Each primary source entity has one lifecycle owner; registration of a second policy for that entity fails. Derived tables can be shared through separate complete owner predicates. Typed entity columns and generated payloads are checked by Rust; registration, schema validation and value validation check uniqueness, column/default compatibility, reference targets, nullability and scalar bounds. An incoming field omission is distinct from an explicit null, and a required local column needs a declared insertion value or database default.

UUID references are stored on source rows, including when a parent is absent. Relationship reads join the reference UUID to the parent's unique UUID. They return an unresolved result when the parent is absent. UUID reference columns allow independent delivery; parent assignment or removal preserves every child row, and queries resolve references against current parents. Integer IDs can remain a caller API detail, resolved against the current parent at command/query boundaries. The child source row retains its UUID reference throughout that lifecycle.

`row_policies!` declares each collection once. A collection provides its tag, entity, generated payload/mapping names, UUID column, portable fields, local defaults and optional limits, references, owner and identity rules. `lists` registers typed `OwnedListPolicy` values as fields of that same payload; encode, initialization and receive all use them. `effects` registers a derived-row mapping and a pure function over the selected source row and optional payload. These functions receive only their declared value inputs. The shared executor performs the bounded list diff and derived-row replacement in the caller's transaction. External I/O and notifications run after commit.

For an existing `metrics` entity with a local primary key, unique UUID column and integer count, an ordinary declaration is:

```rust
sync_orm::row_policies! { pub Metrics, Collection, Payload {
    model: "metrics", schema: "1", collections: {
        Metric => {
            tag: "metrics", entity: metrics::Entity,
            value: Metric, mapping: MetricMap,
            policy: {
                uuid: metrics::Column::Uuid,
                fields: { count: i32 => metrics::Column::Count },
                defaults: {},
                limits: { count => (0, 1000) },
            }
        }
    }
} }
```

The [row-policy tests](tests/row_policy.rs) include complete entity definitions, registration validation and joined source projection. The declaration supplies encoding and ordinary row operations; domain commands still receive the caller's transaction and author the resulting source value explicitly.

An owned list declares its owner predicate, stable item key, portable fields, local defaults and maximum item count. Matched items preserve their local primary keys and local columns. An ordered list also declares its position field and uses contiguous nonnegative positions in payload order. Reordering reserves temporary negative positions inside the transaction before assigning final positions, so swapping items works with a unique owner/position index. The declared mutation bound includes this temporary work. A removed owner deletes only its bounded owned list; independent UUID relationships are unaffected.

`RegistryProjection` admits the sum of the registered read and mutation ceilings before modifying source rows. Source traversal reserves each complete source value's read ceiling, including owned items, and measures the encoded aggregate against the byte limit. Missing UUID assignments and traversal progress remain in the caller's transaction. Tests for these generated paths are in [row_policy.rs](tests/row_policy.rs).

Owner and identity validation is also part of model validation, so it runs on all received candidates before suppression and on transitions to absence. Merge belongs to the engine. The row policy projects its exact selected value, including a lower-revision survivor or absence; authorship belongs to explicit local commands.

Initialization uses stable source keyset cursors and explicit row/byte/mutation budgets. It assigns missing UUIDs transactionally, encodes through the same field declarations, and records completion with the final checked batch. Reopening uses the committed initialization result. The generic initialization state contains progress only.

Acceptance requires real SeaORM parent, child and owner-row entities unrelated to any application. Adding a fourth ordinary entity must require only its entity and registration. Exercise preservation of local columns, different local integer IDs, unresolved UUID references, parent removal/re-addition, owner rejection, rollback after source mutation, initialization restart, lower-winner projection and large parent fan-out. These tests execute the shared row-policy projection.

## Storage design

Use indexed candidate lifetimes, immutable causal context assertions, an exact metadata baseline at a durable history floor, a typed publication journal, and content-addressed manifests/chunks. Keep source snapshot leases durable because the server and CLI may access one database in different processes. Keep receiver comparison coverage, uncommitted fragment cursors, and uncommitted leaf assembly process-local and bounded; restart explicitly expires them.

The selected layout has **ten generic relations**. Candidate payloads store accepted synchronization data. Source changes enter through explicit commands; exact causal context records removed-operation knowledge. Closed candidate bodies and obsolete event history are explicitly reclaimed below the floor. Exact causal observation remains after that reclamation.

Candidate history uses per-dot lifetime indexing. One immutable dot can enter the live set at most once: after removal, monotone observation prevents that same dot from becoming live again. Therefore one birth position and at most one retirement position are sufficient. This avoids rewriting a key's whole concurrent live set every time one candidate changes. Reconstruction retains every concurrent candidate through its own lifetime.

Compaction is required for bounded history retention. A baseline contains exact causal metadata only. Its `context_root` manifest covers every model collection, including empty contexts, through one verified `context_partition` child per collection; a source lease root covers exactly its declared scope. Dependency edges preserve these children and their context manifests. Existing live candidate rows remain the payload source; the baseline stores only causal metadata. Retained journal manifests can duplicate candidate bytes while needed for replay. That real history cost is measured and reported below rather than hidden behind small prefix/context estimates.

## Identity, ordering and transaction axes

All physical UUIDs are 16-byte BLOBs; digests are 32-byte BLOBs; collection tags use their validated UTF-8 bytes with binary ordering. Counters are nonnegative signed-compatible integers, with operation/revision counters positive. SQL uses these binary keys for ordering.

`state_seq` is an internal monotone accepted-state position for one local namespace. Each accepted logical event that changes live candidates or effective context allocates a new state position in the writer transaction. Publication `(replica,generation,sequence,anchor)` remains the externally visible continuity position. Journal rows map the two axes. Snapshot leases capture both. Source state at a fixed public head is reconstructed using its captured internal position.

Separating the axes avoids resetting candidate lifetime coordinates when a publication generation changes. A restore invalidates affected leases before new publication; a new generation establishes its existing state through reconciliation. First contact for an ORM source/scope uses a snapshot whenever the receiver lacks an initialized checkpoint. An initialized zero-position checkpoint is different from no checkpoint. Journal-only implementations may start incrementally at genesis only when genesis is explicitly empty. Checkpoint absence triggers state establishment.

Writer incarnations are per independently writable handle; clones of a handle share its allocator. The allocator burns counters on uncertain/rolled-back attempts and gets a fresh incarnation after reopening. It is separate from the caller's original author/device identity. The handle allocates fresh counters locally. The adapter still rejects detectable reuse and checks retained dot bindings on received candidates. Historical binding checks are limited after their evidence is reclaimed; the stated trusted-replica/unique-writer assumptions remain necessary.

Every accepted mutation takes the namespace writer lock using the existing ORM update/transaction pattern. All synchronization changes, caller projection, journal publication, clock observation and receive checkpoint are in that same physical SQL transaction. The caller commits the transaction supplied to `_on(&DatabaseTransaction, ...)`. Notifications happen after commit. Independent SQL connections and independent processes are supported through the same database locking and durable lease checks.

## Exact ten-relation layout

The adapter owns these relations. `N` below means namespace, `C` collection tag, `V` internal state position, and `D=(writer,counter)` a dot. `sync-orm` owns these tables and exposes their mutation operations to callers. ORM entities and SeaQuery builders define keys/indexes. Schema installation uses the adapter's migration builders.

- **`sync_meta`**: PK N. Model/schema/codec identity; replica and current publication generation; head/anchor; state_seq; observed revision clock; public history floor/anchor; floor_state_seq; baseline-partition manifest; quota counters. Explicit open/import and the namespace writer transaction. Every store operation reads identity/positions. Floor publication updates this row atomically with baseline range rows. Retention: One row per local namespace with durable database identity.
- **`sync_candidates`**: PK `(N,C,writer,counter)`; immutable object UUID, revision author/counter, canonical candidate bytes and digest; retention position; nullable `live_from`, nullable `live_until`. A retained candidate that was always suppressed has no live interval. Candidate acceptance inserts once; removal only closes an open lifetime at the current V. Live lookup, collision checks, projections and historical leaves read it. Changes share accepted-event transaction. Retention: Keep every candidate live at any S at/above floor. Reclaim closed lifetimes ending at/below floor and never-live retained evidence covered by floor, unless an explicit surviving reference needs the body. After history reclamation, only causal context retains the removed operations.
- **`sync_journal`**: PK `(N,generation,sequence)`; unique `(N,V)` for state-changing events; collection tag, canonical event digest, event manifest and anchor_after. Accepted local/received causal changes append in writer transaction. Incremental readers and continuity checks read it. Retention: Keep the required contiguous suffix above floor and all declared tail pins. Floor retains its exact anchor. Delete older rows in bounded batches after baseline publication.
- **`sync_checkpoints`**: PK `(N,source_replica,source_generation,scope_digest)`; actual normalized scope identity, sequence/anchor and directional completed_at. Row absence means uninitialized. Atomic receive/final completion transaction; session orchestration reads it. Retention: Durable until explicit source/namespace lifecycle cleanup. It records directional receive progress for that source and scope.
- **`sync_context_ranges`**: PK `(N,C,V,ordinal)`; exact lower/upper bounds and a verified context-manifest reference. Rows at `floor_state_seq` are the complete baseline partition; later rows are accepted context assertions. Accepted-event transaction appends assertions. Compactor installs the baseline rows at F and publishes floor in one transaction. Membership/snapshot/compactor readers use the current floor and V bound. Retention: Rows below the active floor can be reclaimed. Baseline rows and later assertions remain while needed. A completed range persists beyond its receiving session.
- **`sync_context_intervals`**: PK `(N,context_manifest,writer,first)` with inclusive last; canonical disjoint intervals. `[1,prefix]` is the prefix interval; remaining intervals are exceptions. Empty context uses zero interval rows. Created from a fully validated immutable context in the same transaction that publishes its manifest/index. Membership and normalization read it. Retention: Shares the referenced context manifest's lifetime.
- **`sync_manifests`**: PK `(N,manifest_digest)`; fixed kind, content digest, encoded length, item count, fragment count and validated immutable metadata. Existence means complete validation succeeded. Context/event construction publishes atomically; source fragments, replay, baseline and GC read it. Retention: Keep while reachable from accepted state, retained history or a live durable pin.
- **`sync_chunks`**: PK `(N,manifest_digest,ordinal)`; offset, fragment digest and immutable bytes. Insert with a validated manifest; bounded fragment readers read by ordinal. Publication requires a completely validated manifest and all its chunks. Retention: Delete with unreachable manifest. Byte sharing occurs at manifest granularity.
- **`sync_manifest_edges`**: PK `(N,parent_manifest,child_manifest)`; inverse child index. Records immutable manifest dependencies. Written during manifest validation/publication and removed during GC. Retention traversal reads it. Retention: Exactly follows manifest ownership. This relation avoids parsing every retained payload to find dependencies during GC and prevents reclaiming source-live evidence still referenced by a later event.
- **`sync_leases`**: PK `(N,snapshot_or_pin_id)`; source generation/head/anchor, internal S, exact scope, expiry, building/ready/revoked state, retained-root manifest and immutable descriptor when ready. Short explicit snapshot/build lifecycle transactions create/update/revoke; all serving, floor-switch and GC transactions consult it. Ready descriptor identity is immutable. Retention: Ready source views survive restart or are explicitly revoked durably before pins are released. Unfinished builds can be revoked or expire. Candidate payloads remain in the lifetime index.

A baseline row is the same kind of causal assertion as any other row: “these dots have been observed throughout this interval.” Its position F and the meta floor identify the baseline, rather than a disguised deleted-object status. Reclaiming a deleted key's eligible history leaves its observation context in the interval index.

The candidate relation is a retained temporal index. Its retirement position is immutable until the eligible history row is deleted. Source payloads are immutable. Event encodings that carry full candidates retain those bytes in journal chunks too; physical size accounting includes that duplication until reclamation.

### Private source-build nodes

The ORM may persist an unfinished source-build metadata chain as manifest kind `6`, which is reserved for adapter-internal work. Version 1 node bytes contain a one-byte version, a presence byte and 32-byte digest for each of the previous node and optional completed child, followed by a big-endian 32-bit payload length and at most 4096 payload bytes. The node digest is BLAKE3 over the domain `sync.orm.private.work-node.v1` followed by a zero byte and the node bytes. The previous and child digests are ordinary dependency edges. A building lease roots the current head in the same transaction as each checkpoint. The node remains private until final validation. Readers for protocol manifests reject kind 6. Expiry or revocation releases the lease root, after which normal bounded DAG collection reclaims unreachable nodes and their descendants.

A context being emitted may have a private reservation, storage kind `7`, at its eventual manifest digest. Its immutable metadata records the expected protocol reference; independently rooted private nodes retain the reservation and bounded fragments. Ordinary manifest readers reject this kind. The context builder verifies stored fragments and canonical content under the active lease and exact retained root before atomically promoting the reservation to a Context. Repeated reservations and identical fragment writes are idempotent; conflicting bytes fail. Unreachable reservations and fragments follow ordinary manifest reclamation.

### Required indexes

- Candidate direct dot PK catches retained cross-key/content conflicts. Current-key traversal: `(N,C,live_until,object,writer,counter)` with `live_from IS NOT NULL`; historical key traversal: `(N,C,object,writer,counter,live_from,live_until)`.
- Journal primary key gives strict sequence scans; `(N,V)` maps accepted state positions to publication positions.
- Context interval PK supports predecessor membership inside one manifest/writer. An additional `(N,writer,last,first,context_manifest)` index assists writer admission/known-dot checks; membership still applies exact key-range qualification.
- Context assertions use `(N,C,lower_bound,V,upper_bound)` plus the primary sequence index. Baseline rows have disjoint ranges, so one predecessor range lookup suffices for the baseline contribution. Later assertions are scanned in bounded keyset batches and tested exactly.
- Lease indexes support active/expiry, minimum pinned S/head, and retained-root lookup. Add `(N,manifest)` on the journal and `(N,context_manifest)` on range assertions for direct retention-root checks. Edges have both parent and child traversal indexes.

Encode endpoints as ordered tagged byte strings: negative infinity, finite UUID bytes, positive infinity. Bounds therefore have one explicit binary order. The finite key is encoded with the same finite tag when testing interval containment.

Later overlapping assertions may require a scan. `LIMIT` bounds returned rows; query plans determine how many rows SQLite examines. Use predictable primary-key batches where needed, count work, and compact before the uncompacted assertion suffix becomes impractical. Exhausting an admitted budget returns resumable incomplete work or a retryable limit.

## State meaning and exact reconstruction at S

Let F be the active floor_state_seq. Let B_F(k) be the context of the unique baseline segment containing key k, or empty genesis context when F=0 and no baseline has yet been needed. Let A contain accepted context assertions with `F < V <= S`. Then:

```text
K_S(k) = B_F(k) union union(context(a) for a in A if a.range contains k)

live_S(k,d) iff candidate.live_from is present
                 AND candidate.live_from <= S
                 AND (candidate.live_until is absent OR candidate.live_until > S)
```

This reconstruction reads the candidate lifetime index and qualified contexts. Candidate bytes, revision, key and dot remain immutable. A retirement recorded later at N>S leaves `N>S` true in the predicate, so a previously opened view at S remains unchanged. An insertion after S has `live_from>S` and is excluded. Closed candidates remain retired. Context assertions are immutable and included only through S. Switching from an older baseline to a newer F<=S preserves K_S by exact union equivalence.

A new accepted live dot, or an explicit keyed observation whose binding is known from the typed delta, adds a full-collection context assertion containing those exact dots. A received complete source range adds the qualified source context and a full-root assertion for individually received source-live dots, including those suppressed locally. These sets record the exact operations observed by the accepted event. This preserves the engine rule that an individually observed live dot is globally observed while an otherwise unbound range observation stays qualified.

The adapter stores the effective observation function directly as baseline plus assertions. Full-root assertions provide the same globally observed facts. Reference comparisons export complete normalized segments and compare with the reference causal join semantically.

At snapshot creation, capture source public head/anchor and S in a durable building lease in a short transaction. Construct only normalized causal metadata and aggregate hashes, reading candidate history at S in bounded pages. Publish a ready immutable descriptor only when construction succeeds. A valid lease pins the necessary candidate/history/context basis and post-head tail. Each database transaction finishes before a network request begins.

Ready leases retain the metadata-root manifest needed to serve their normalized context partitions. Live candidate leaves come from the lifetime index at S. The lease retains metadata and candidate-history pins. Summaries hash all surviving candidates and exact normalized contexts for the exact interval. Hash input includes the complete surviving candidate set.

## Bounded ordinary operations

### Local command

An owned author handle allocates a fresh dot from its local counter. In the caller transaction, lock meta, read only the current candidates for the command's key, validate the typed observation, calculate before/after winners, reserve the entire supported logical operation, and append the key delta. Insert the new candidate and close only the observed old lifetimes; append exact context assertions if newly observed dots require them. Apply the caller's repository assignment/pending outcome and commit together.

Single-key reads constrain both ends of the UUID interval. Its upper bound is the next UUID, or unbounded for the maximum UUID. Local assignments and incoming key deltas read candidate bodies only for that key. The query-count regression compares assignments before and after a populated key range using SeaORM's actual statement metrics.

A removal closes observed current lifetimes and authors a remove event. The required observation knowledge already exists for those dots. Explicit narrower observations name an exact subset of current candidate dots.

### Received keyed delta

Validate the complete event and original-author structural rules, including all additions and removals. Look up retained dot bindings by index. Read current candidates for that one key and effective observation through baseline plus qualifying suffix assertions. Apply the exact observed-remove join. Every decoded candidate is validated even when already suppressed; observing its logical revision counter is separate from whether it survives or changes the displayed winner.

Accepting an observation also establishes its complete interval index in that transaction, even if immutable manifest bytes were received earlier as a dependency. Application validates interval-index completeness separately from manifest existence. A contiguous writer prefix directly represents all observed counters through that prefix. Range comparison includes these prefixes, including ranges with no live candidates.

### Received complete range

Assemble and validate a finite leaf and all context dependencies outside the writer transaction under the staging budget. Incoming key/dot order, source context membership and complete boundaries must all be verified. Under the namespace lock, prevalidate incoming retained-dot collisions against the original receiver before processing any subrange. This preserves the atomic validation rule.

Merge the ordered union of current local keys in the interval and staged source keys, in bounded batches. Use the old effective context for each merge. Stream exact before/after candidate sets and projections. Append the qualified assertion and required individually observed dots, the range event and its retained live/context evidence, then commit atomically.

A leaf that exceeds the supported atomic mutation/work budget is subdivided before acceptance. A single unsplittable key/event over the supported limit returns an explicit limit error. Admission bounds incoming events, resulting concurrent candidate bytes and effective context. Accepted states must remain exportable and compactable under supported logical limits. A conservative context-size upper bound may trigger compaction and retry before new authorship; compaction preserves every observed dot. Source leases also reserve the retained history/storage they can block. Transaction work and memory bytes have separate admission bounds. Whole-key concurrency and caller fan-out limits are part of that admission.

Projection is determined by exact before/after selected values. Removing the highest candidate can reveal a lower-revision survivor. Compare exact before/after selected candidates and invoke projection whenever they differ, including decreases and transitions to absence. Hidden-only and context-only changes still receive journal entries even if no business assignment is needed. Pending work is guarded by current candidate identity.

## Receiver restart and source-lease policy

Receiver session coverage, page cursors, fragment cursors and uncommitted leaf buffers are process-local. They are bounded by the engine limits: logical apply graph 8 MiB default / 64 MiB hard cap, total staging 64 MiB / 512 MiB, and 4 / 16 simultaneous stages. Count the root event and its transitive context/live dependencies. Also bound decoded items and resident working memory.

Incomplete transfers may resume while the process and stage are alive. On restart they return expired/stale-stage and restart comparison or transfer. A cached complete validated manifest can be reused; partial chunks remain uncommitted staging. Uncommitted assembly stays in bounded memory; manifests/chunks and accepted references are published atomically when applying a completed logical input. Publishing the complete input with its accepted references makes its retention atomic.

For a complete range, SQL commit precedes marking that interval complete in the in-memory ledger. Crash between those actions loses only session progress; accepted data/context/history survives and can be compared again. Final checkpoint/completed_at publication takes the session lock, verifies every interval was committed and required descriptors remain valid, then commits checkpoint and completion metadata in SQL. Crash before that transaction leaves no completed checkpoint; crash after it preserves a truthful complete checkpoint even though the in-memory ledger disappears.

The endpoint uses the engine's `ReceiverLedger<M>` for fragment and coverage validation. An asynchronous admission lock covers preparation, SQL mutation, source projection, commit and ledger finalization. The lock and transaction are released after each operation, before the next network request. The prepared evidence retains the original source scope and committed summary. The SQL join uses current receiver state, while equal-range admission compares the pinned local view. Projection receives only the transaction and read-only accepted-state access. Failure rolls back SQL; cancellation after commit can replay the same evidence and then finalize while preserving the publication head.

Source leases are durable because a CLI compactor must see a server's pin between requests. Every process checks the same lease table. A ready lease can be served after restart from its stored descriptor, metadata manifest and S. A process may instead revoke it durably before releasing roots. Expiry/revocation is checked before every operation. Only ready leases are advertised. Interrupted builds may be explicitly revoked or retained until bounded expiry. Accepted context survives receiver session loss.

Baseline/context construction also uses a durable internal pin for its read position and constructed root. Each published construction root and its pin update share a short transaction. Its continuation cursor can remain process-local: losing it abandons the build and preserves the current floor. This avoids a separate build-job relation. Pin creation/revocation and manifest GC use the same namespace serialization, so another process cannot free an object between publishing it and pinning it.

## Exact floor advancement and reclamation

The compactor advances through bounded operations. It uses these steps:

1. Select proposed internal F and corresponding publication floor `(f,anchor_f)`. F cannot exceed the minimum internal position required by any live source/build pin; f cannot cross a live pinned journal tail. New snapshots capture current heads, and all pin changes serialize with the final floor check.
2. Create a durable internal build pin and capture the old floor/baseline. Construct `K_F` from that baseline plus assertions through F. Normalize exact bounds into a complete disjoint collection partition and union exact writer intervals, preserving gaps. Stream construction under work limits and publish immutable context manifests/indexes as pinned metadata. The baseline contains causal metadata only.
3. Validate the complete normalized partition and its root manifest. Before the floor switch, verify the old basis is still valid and recheck every live pin transactionally. If a different compactor changed the basis, restart or reuse only proven equivalent work; each continuation requires validation against its basis.
4. In one namespace writer transaction, replace existing context-range rows at F with the complete baseline rows at F, set meta's floor_state_seq, public floor/anchor and baseline root, and retire the build pin only after the new root is retained. Later assertions and candidate mutations remain untouched. Cap the baseline row count so this final metadata transaction fits its mutation budget. A crash exposes either the old complete floor or the new complete floor.
5. After publication, queries ignore range assertions below F. Reclaim those rows and journal entries through the public floor in bounded transactions, respecting any surviving explicit reference. The anchor at the floor remains in meta. Delete candidate history with `live_until <= F`; delete eligible never-live evidence; preserve every open lifetime and every lifetime closing after F. A candidate born before F and still live is retained with its original immutable body and birth position.
6. Use a concrete DAG reclamation rule: a manifest is collectible only when it has no direct durable root and no incoming dependency edge. Check journal, context-range, meta-baseline and active lease roots through their indexes. Existing physical history rows may conservatively retain their manifests until their row batch is deleted. Construction publishes children before parents, so the validated dependency graph is acyclic. Removing an unrooted parent and its outgoing edges eventually makes unreachable children collectible; no whole-graph mark or optional reference-count framework is required. Under the namespace writer lock, recheck eligibility and delete one admitted manifest, its chunks, derived context intervals and outgoing edges atomically. This prevents another process from pinning partially reclaimed content. Scan manifest candidates in bounded keyset batches and repeat passes as parent deletion exposes children. Each accepted manifest has a finite byte/item/dependency bound; GC must reserve enough work to delete any single manifest the store admitted. A smaller caller budget returns required/incomplete work rather than leaking the object or exposing partial deletion. A child still referenced by an event above the floor remains, even if its original event was below the floor. Expired/revoked leases release their roots transactionally before collection.
7. SQLite freed pages become reusable database space. Returning file bytes to the filesystem is a separate explicit maintenance operation, such as a supported vacuum policy; it may require extra space and longer local work. It is not silently run on every receive or represented as network synchronization progress.

A ready lease at S remains correct after advancing the floor to F<=S because its retained root and the suffix reconstruct the same K_S. While a baseline or snapshot is being built, its lease instead pins the captured input floor and baseline generation, the required F..S history, and any staged output generation. Expired leases remain pins until their revocation commits. A receiver with an incremental checkpoint below floor must reconcile from a complete current view; that view's exact context prevents stale reappearance even though old candidate bodies and events are gone.

Context assertions use the nil baseline generation. Each normalized baseline is written under a fresh generation in the same context-range relation. Readers select the active generation at the floor and nil-generation assertions after it. Publication switches the active generation, floor, anchor, and root together; bounded maintenance may later remove obsolete generation rows once no unrevoked lease pins them as input or output.

A source lease can own an inactive output generation containing its verified normalized view. These rows belong to the source view's context metadata; accepted assertions use the nil generation. A nullable logical `context_digest` is populated for verified staged rows and checked against existing values for the same context manifest. Ready leases retain their output-generation pin until revocation or expiry. Generation reclamation protects both captured input and owned output generations while their leases remain active.

There is no finite universal bound on context size with arbitrary actor churn and delivery gaps. Admission limits can refuse new work, expiry can release a source pin before compaction, and callers can retry/reconcile; none of those may discard accepted causal evidence. Worst-case exact metadata can remain proportional to operations. The compact create/remove case is a favorable workload, not a universal storage guarantee.

`Maintenance::advance` commits one bounded operation and then updates its caller-owned continuation. Its phases revoke expired leases, build a baseline, prune eligible history, reclaim obsolete baseline rows and reclaim unreferenced immutable objects. Processes operating on the same namespace, replica generation and active baseline generation share a deterministic baseline request ID. They resume the same persisted build instead of creating builds that pin each other. Losing the in-memory cursor permits recovery from the stored checkpoint. An expired or obsolete continuation is released before restarting. Storage errors leave the last committed continuation intact.

## Resumable source views

Opening a source view captures accepted state position S, publication generation/head and baseline floor F together. A durable build lease pins the reconstruction basis at F, the required history through S and all committed partial outputs. Every continuation validates namespace, generation, scope, lease expiry and the retained basis. Candidate lifetimes are read at S; context reconstruction uses the baseline at F plus assertions through S. Later writes stay outside the view. Build progress and immutable output references commit together; only complete validation publishes the ready descriptor and its retained context root.

The endpoint validates a caller's complete work allowance and caps each source request at 1,024 scanned rows and 8 MiB. A snapshot-open request may commit several short transactions, reserving each step's rows, bytes and mutations from one aggregate allowance. The first step reserves the full allowance before any database read and releases unused capacity only after commit. A successor plan is derived from the updated in-memory state, used only after commit and bound to the next transaction's exact cursor; a competing advance invalidates that internal plan. Variable-volume work retains its full allowance, and an initial boundary or candidate-count scan uses at most five rows before switching to the full allowance when records are found. The request starts at most `min(64, max_requests)` transactions, and stops starting work after a cooperative 200 ms deadline. Range comparison and splitting retain their bounded continuations.

The original work limits remain part of the serialized build identity; transient transaction allowances are excluded. When those limits permit, a fixed-work step reserves five content rows, sixteen mutations and twice the serialized checkpoint size plus the staged scope/descriptor bytes and 16 KiB. Otherwise it retains the original allowance. These reservations cover checkpoint growth, private nodes, fragments, dependencies and lease-root changes. Variable-work phases require their full reservation; if it no longer fits, the request returns its latest committed cursor. A charge is validated before commit and only unused reserved capacity is refunded afterward. The aggregate budget includes committed and failed attempts throughout the request. Transactions yield after commit. A transaction admitted before the cooperative deadline may finish after it.

An external retry with an older cursor or no cursor resumes the retained request's latest committed position; a future cursor, wrong generation or changed scope fails. This differs from an internal successor plan, which requires the exact expected cursor. Database reopen resumes committed work. An error after earlier steps committed remains an error, and a retry can recover that prefix. Cancellation after admission prevents further work while the revoked lease is retained. Request IDs are not reused after release or expiry; pre-admission cancellation and indefinite cancellation retention are not supported by this adapter.

`max_rows_scanned` counts explicitly inspected content rows: candidate headers and bodies, context assertions and intervals, fragments and variable dependency traversal. Fixed bounded namespace and lease lookups are tracked separately; SQLite's internal B-tree visits are not counted as content rows. Every write, including checkpoints, lease roots and cursors, consumes mutation allowance. An indivisible step that cannot fit returns `LimitTooSmall`.

Source construction keeps one ordered segment root per selected collection in its durable build cursor. Partition and summary passes begin at that root. Private nodes with at most two dependency edges are validated in one read operation when at least five scanned rows and 4,167 body bytes are available; smaller budgets preserve the header/body/edge continuation. The collection index references the retained chain through the existing build cursor.

Source construction and comparison use bounded ordered header and body batches at the lease's captured state position. Count and split selection read only headers and lengths; hashing and leaf reads fetch bodies and validate their canonical encoding, typed identity, size and digest before contributing to a summary or serving a leaf. Source-work accounting charges every fetched header and body to the row and byte allowance, including prefetched rows that a split does not consume. A continuation records the last consumed key and dot exclusively; a pending header can carry a body read into the next operation. Small allowances retain the single-row path. Every batch reads the same captured state position.

Candidate scans reserve their checkpoint before reading. Each fetched header consumes one row and 128 bytes; each body consumes one row and its admitted length plus 96 bytes. Continuations retain pending body work and bound serialized output growth. Boundary scans read at most the minimum of available rows, available bytes divided by 64, and 1,024 assertion headers. They validate the entire admitted header page before advancing and preserve separate cursors for the active baseline and later assertions. Both phases retain the state-position bound S.

Splitting reuses candidate count and byte totals only from the pinned descriptor's exact root summary or an exact completed summary of the requested subrange. Otherwise it performs a bounded header count. The split boundary remains deterministic, including empty and single-object intervals. Summary construction validates candidate bodies and context commitments before publishing its result.

Context membership reads ordered assertion pages with explicit row limits and a continuation; absence is returned only after the relevant coverage is complete. A global-coverage probe reads at most one additional assertion to detect work-limit overflow. Interval indexing inserts and checks bounded batches while charging every logical interval, including an existing entry. It rejects conflicting stored intervals and preserves gaps. During one source-build transaction, a context builder validates its lease, captured basis and retained root once, checks those identities for each bounded step, and ends the session when a root changes. A later transaction validates again.

Range joining may decode a retained context manifest once per digest and reuse that value within the same transaction. Each assertion still consumes its applicable byte, fragment and row allowance. Decoded context lives only for its receiving transaction. Before committing a batched continuation, admission must bound growth of its serialized output state as well as fetched rows, encoded bytes and mutations.

Retained manifest reads validate metadata before allocating the declared body. A single fragment uses that validated length directly in its body query. Multiple fragments use ordered batches of at most 96 size-only headers and a body batch of at most one page. Every body query constrains the stored length before allocation. Reads check contiguous ordinals and extents, each fragment digest and the complete content digest. Fragment and logical-body limits remain independent of SQL batch size.

Root emission records the dependency set contributed by its authenticated content. The set is bounded by the collection count. Verification walks stored dependencies in order and rejects both unexpected dependencies and missing expected dependencies before publication. The remaining set and source cursor share the same transaction.

## Public adapter methods and validation

`OrmReplica<M>` uses typed collections with stable tags and the engine's fixed codec. It implements atomic store and snapshot capabilities. Inherent `write_local_on`, `apply_page_on`, `apply_staged_event_on` and `apply_range_on` methods accept `&DatabaseTransaction`; the caller retains commit ownership. The endpoint implements fragmented-event and complete-range commits through the receiver capability. Exact before/after projection can stream through a transaction-bound caller or return a bounded batch. The caller supplies business reference policies; the adapter projects each accepted assignment in the existing receive transaction.

Every decoded candidate is validated before suppression. If an affected known key has no surviving candidate, invoke the caller's empty-value validation, including a late suppressed arrival with no previous displayed value. Trusted sources preserve original authorship; an author UUID is not a signature. Structural owner restrictions remain caller validation. Storage code and schema use caller-defined model and collection tags.

Use SeaORM entity operations and SeaQuery for schema, CRUD, indexed ranges, predicates, joins and locking. Backend-specific SQL requires a demonstrated missing capability. Normal authoring reads one affected key and its relevant exact context. Supported budgets include scanned rows, decoded allocation, transitive dependency bytes, candidate concurrency and transaction mutations.

Source schema validation uses SQLite's `pragma_table_info`, `pragma_index_list` and `pragma_index_info` table-valued functions through SeaQuery's function and select builders. Descriptor appends use expression builders for null handling, bound bytes and the BLOB cast. SeaQuery 1.0.2 has no dedicated SQLite concatenation operator variant, so only the fixed `||` token uses `BinOper::Custom`. These operations target SQLite.

Source rows in an existing database are preserved. An incompatible scalar store requires an explicit import with verified provenance. Initialization/import must explicitly establish its provenance or reject before mutation with actionable details. Fresh installation and preservation/refusal are separate acceptance cases.

## Acceptance

Use a non-music model with a real primary entity. Verify caller projection failure rolls back candidates, contexts, journal, clocks and progress; removing a winning candidate can reveal and project a lower-revision survivor. Check historical leaves and exact contexts at random retained positions against reference replay.

Independent database connections must preserve a leased view while another writer and compactor run. Test open candidates born before the floor, retirements after the floor, gaps, overlapping qualified ranges, active/expired/revoked leases, retained dependency graphs, and complete views after floor advancement. Rust process-interruption tests cover commit-before-coverage, baseline publication, final checkpoints and reclamation boundaries.

Measurements use the actual SeaORM schema and operation paths, and identify SQLite journal mode, transactions, pins/live rows, query plans, duration, peak memory and allocated/reusable file bytes. Logical context size and synthetic schema size are distinct measurements. Runtime tests and measurements establish this coverage.

Source regressions compare one-row, byte-limited and broad budgets against identical captured values, including a nonzero baseline floor and later writes. They cover lost replies after multiple commits, database reopening, competing callers, cancellation and storage failure after committed progress. Missing, extra or corrupted root dependencies reject descriptor publication and preserve the last committed checkpoint. Tests enforce aggregate reservations and the one-, two- and 64-transaction request limits. The one-record, fifteen-collection diagnostic requires fewer than 2,000 source continuations; larger measurements report collection, segment and candidate counts separately.

Manifest tests cover multiple SQL batches, bodies larger than one page, missing or reordered fragments, invalid offsets, same-length corruption, enlarged stored bodies and forged fragment digests under independent byte and fragment limits. Source-summary tests compare cached and uncached split results for empty, single-object and multi-object intervals. Relay tests use a non-music model to compare candidate sets and exact observations against an independent reference, then exchange every ordered pair after graph convergence; obsolete incremental delivery must preserve publication heads.
